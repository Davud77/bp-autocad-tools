# Дорожная карта

Здесь записываются планы. Когда пункт сделан, он отмечается `[x]` и указывается версия.
Детали реализованного переносятся в `CHANGELOG.md` и `docs/RELEASE-*.md`.

Статусы: `[ ]` — запланировано, `[~]` — в работе, `[x]` — сделано, `[?]` — нужно решение или проверка.

## Производительность (зависания и микрофризы)

Анализ от 5 ноября 2026 г. Плагин тормозит AutoCAD не в своих командах, а в фоне: пять обработчиков
`Application.Idle` и подписки на события чертежа работают всё время, пока открыт AutoCAD.

### P1. Фоновая синхронизация штампа — главная причина

Файлы: `Services/StampSignatureTracking.cs`, `Services/StampSignatureDwgService.cs`, `Services/StampTextLayoutService.cs`.

Проблема. После вставки формата или открытия окна свойств штампа слежение включается и работает до закрытия
AutoCAD, во всех открытых чертежах. Любое изменение любого блока запускает через секунду полный проход:
весь чертёж, все подписи (PNG декодируется заново), все поля (`EvaluateFields`). Ещё раз в секунду
копируются свойства DWG, чтобы сравнить их с прошлыми.

Зачем это нужно. При изменении формата листа (динамический параметр рамки) AutoCAD создаёт новое анонимное
определение блока. Подписей в нём нет, а длинные поля штампа теряют разметку. Слежение возвращает их на место.

Решено (5 ноября 2026 г.): **следить только за рамкой `WM_FORMAT`** и обновлять штамп только в моменты,
перечисленные ниже. Постоянный опрос раз в секунду (`Application.Idle`) убирается полностью.

Когда штамп обновляется (подписи на месте, длинные поля с переносами):

1. После команды, в которой менялся блок `WM_FORMAT` (смена формата, перенос, копирование, вставка рамки,
   правка атрибутов). Один раз, после окончания команды (`CommandEnded`/`CommandCancelled`/`CommandFailed`).
   Во время перетаскивания ручки ничего не делается.
2. После команд регенерации: `REGEN`, `REGENALL` (`РЕГЕН`, `РЕГЕНВСЕ`).
3. После команды обновления полей: `UPDATEFIELD` (`ОБНПОЛЕ`).
4. Перед сохранением: в `CommandWillStart` команд `QSAVE`, `SAVE`, `SAVEAS` (`БСОХРАНИТЬ`, `СОХРАНИТЬ`,
   `СОХРАНИТЬКАК`). Автосохранение (`.sv$`) не трогается.
5. Как и сейчас: при вставке рамки и по кнопке «Применить» в окне штампа.

В пунктах 2–4 сначала выполняется дешёвая проверка: есть ли в чертеже `WM_FORMAT` и изменилось ли что-то
с прошлого обновления (рамки, свойства DWG, подписи). Если ничего не менялось, работа не делается.

Задачи:

- [x] 1.9.0: Реагировать только на блок формата. В `ObjectModified`/`ObjectAppended` сравнивать `BlockTableRecord`
      и `DynamicBlockTableRecord` с запомненными `ObjectId` блока формата этого чертежа (основное и анонимные
      определения). Остальные блоки игнорировать без открытия объектов. Событие только ставит флаг.
- [x] 1.9.0: Не следить за чертежами без блока формата. Подписываться на события чертежа, только когда блок
      формата есть или его вставили.
- [x] 1.9.0: Убрать `Application.Idle` из `StampSignatureTracking`. Обновление — по флагу после команды и по
      командам `REGEN`/`REGENALL`/`UPDATEFIELD`/`QSAVE`/`SAVE`/`SAVEAS`. Сравнивать глобальные
      (английские) имена команд (`GlobalCommandName`), чтобы работало в русской и английской версиях.
- [x] 1.9.0: Не вызывать `Editor.Regen()` из обновления, запущенного командой `REGEN`/`REGENALL`, чтобы не было
      двойной регенерации и зацикливания.
- [x] 1.9.0: Свойства DWG сравнивать с прошлыми только в эти моменты, а не раз в секунду. Отдельно — после
      `DWGPROPS` (`СВОЙСТВАЧЕРТЕЖА`).
- [?] 1.9.0, проверить в полном AutoCAD: Проверить, что изменение чертежа перед сохранением попадает в сохраняемый файл и не оставляет
      чертёж помеченным как изменённый после сохранения.
- [x] 1.9.0: `StampTextLayoutService.Apply`: искать рамки через `GetBlockReferenceIds` блока формата
      и его анонимных определений, а не обходом всех объектов чертежа.
- [x] 1.9.0: Убрать `database.EvaluateFields` по всему чертежу. Обновлять поля только изменённых атрибутов. Полный пересчёт полей остаётся только при реальном изменении свойств DWG.
- [x] 1.9.0: `StampSignatureDwgService.GetGeometry`: сначала проверять `table.Has(name)`, и только при отсутствии
      блока декодировать PNG. Имя блока (SHA-256) считать один раз и хранить вместе с подписью.
- [x] 1.9.0: Кэшировать загруженные подписи по чертежу. Перечитывать Xrecord, только когда он изменился.
- [?] На будущее: проверить, можно ли хранить подписи так, чтобы AutoCAD сам переносил их в новые
      анонимные определения. Тогда слежение за подписями станет не нужно совсем. Требует опыта на
      AutoCAD 2025–2027.

### P2. Сумма длин выделения в строке состояния

Файлы: `Services/SelectionLengthService.cs`, `ViewModels/SumLengthViewModel.cs`.

Проблема. При каждом изменении выделения плагин открывает все выделенные объекты и считает длину.
Сплайны считаются медленно. При Ctrl+A в большом чертеже это пауза на каждое изменение выделения.
Если открыто окно «Сумма длин», тот же расчёт выполняется второй раз.


Решено (5 ноября 2026 г.): **левый клик копирует значение, правый открывает меню «Включить/Выключить»**.

- [x] 1.9.0: Левый клик по полю «Сумм. длина» копирует текущее значение в буфер обмена (число в единицах
      чертежа, как показано в поле). Если подсчёт выключен или значения нет, клик ничего не копирует.
- [x] 1.9.0: Правый клик открывает меню с пунктом «Включить подсчёт» / «Выключить подсчёт».
- [x] 1.9.0: Поле остаётся видимым и в выключенном состоянии («Длина: выкл.»), чтобы его можно было включить
      обратно правым кликом.
- [x] 1.9.0: Состояние вкл/выкл сохраняется в настройках (`settings.json`) между сессиями.
- [x] 1.9.0: Выключено — значит ноль нагрузки: модуль отписывается от `ImpliedSelectionChanged`,
      `CommandEnded`/`CommandCancelled`/`CommandFailed`, событий документов и от `Application.Idle`.
      Не вызываются `SelectImplied`, `LockDocument`, транзакции и обновление строки состояния.
      Остаётся только обработчик клика по полю.
- [x] 1.9.0: Ограничение: при выделении больше N объектов (например, 5000) не считать автоматически,
      показывать «Длина: много объектов — клик для расчёта».
- [x] 1.9.0: Не считать дважды: при открытом окне «Сумма длин» индикатор берёт результат окна или окно — индикатора.

### P3. Опрос интерфейса раз в секунду

Файлы: `App.cs`, `UI/RibbonController.cs`, `UI/ClassicUiController.cs`, `UI/ContextMenuController.cs`.

Проблема. Раз в секунду проверяется лента, контекстное меню и классическое меню, создаётся объект
процесса (без `Dispose`), читается `WSCURRENT`, при классическом UI идут медленные COM-вызовы.

План:

- [x] 1.9.0: Имя процесса (`acad` или консоль без интерфейса) проверять один раз при запуске и запомнить.
- [x] 1.9.0: Таймер в `Idle` оставить только до первой успешной инициализации (лента, меню, плоттер, шаблон QNEW),
      затем отписаться от `Idle`.
- [x] 1.9.0: Ленту восстанавливать по событиям: `ComponentManager.ItemInitialized` (без `RibbonServices`: сборка AcWindows не подключена) —
      плюс разовая проверка после `CommandEnded` для
      `CUILOAD`, `MENULOAD`, `WORKSPACE`, `RIBBON`.
- [x] 1.9.0: Смену рабочего пространства ловить через `Application.SystemVariableChanged` (`WSCURRENT`).
- [x] 1.9.0: Один интерфейс за раз по галочке «Классический интерфейс»:
      - включена — показываются классические меню и панель, вкладка BotPlus на ленте удаляется;
        видимость панели больше не зависит от того, видна ли лента;
      - выключена — показывается только вкладка на ленте, классические меню и панель скрываются
        и больше не проверяются.
- [x] 1.9.0: Переключение галочки применяется сразу, без перезапуска AutoCAD.
- [x] 1.9.0: COM-ошибку `0x80210045` («Свойство недоступно в текущем состоянии») обрабатывать как «повторить
      позже, после команды», а не каждые 30 секунд.

### Уточнения при реализации 1.9.0

- Слежение за штампом теперь включается при запуске AutoCAD, а не только после вставки форматки или
  открытия окна штампа. Это дёшево (одна проверка таблицы блоков после команды в чертежах без форматки)
  и восстанавливает подписи при смене формата в любом открытом DWG.
- После `U`/`UNDO`/`REDO`/`MREDO` штамп не обновляется: отмена сама возвращает прежнее состояние.
- Свойства DWG при открытии чертежа берутся за исходные: открытие и `РЕГЕН` без изменений не помечают
  чертёж как изменённый.
- Индикатор длины: без выделения поле показывает «—» и не скрывается, чтобы правый клик был доступен всегда.
- Записи об установке плоттера хранятся отдельно для каждой версии AutoCAD (2025–2026 и 2027 на одном ПК
  не перезаписывают друг друга).
- Индикатор длины не запускается в Core Console (`accoreconsole`): там нет строки состояния, и обращение
  к ней завершает процесс.
